the GET /kyc/status response shape the mock body must decode into:
```swift
nonisolated public struct KYCStatusEndpoint: APIEndpoint {
    public typealias RequestBody = EmptyBody
    public struct Response: Decodable, Sendable {
        public struct Artifact: Decodable, Sendable {
            public let artifactID: String        // wire: artifact_id
            public let status: String            // "pending_review" | "verified" | "rejected"
            public let rejectionReason: String?  // wire: rejection_reason — nullable
        }
        public let overallStatus: String         // wire: overall_status — "pending" | "under_review" | "verified" | "rejected"
        public let artifacts: [Artifact]
    }
    public let path = "/kyc/status"
    public let method: HTTPMethod = .get
}
```
APIClient decodes with `.convertFromSnakeCase`, so the mock JSON body uses
snake_case keys (`overall_status`, `artifacts`, `artifact_id`, `rejection_reason`).

From validationLedger/Core/Networking/Mock/MockDefaultFixtures.swift —
the existing dispatch pattern this plan extends. The switch is keyed on
`(method, path)`; each handled case returns `make200(body: <builder>(), url:
request.url)`; the `default` branch returns `nil` (built-in 404). The whole
file is wrapped in `#if DEBUG`. The post-submit upload endpoints already return
`under_review` (`kycSubmitResponseJSON()`), so the status screen reached straight
after Submit must agree: `overall_status` = `under_review`.

IDs to echo, so the status body for the device mock uses an empty `artifacts`
