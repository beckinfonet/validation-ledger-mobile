    ```swift
    // validationLedger/App/AppSession.swift
    // Mutable session-scoped state holder. Referenced by AppContainer.session.
    //
    // Currently tracks:
    //   - trustTier: TrustTier — set by /device/register + /device/heartbeat responses (D-12)
    //
    // Why a class (not a struct on AppContainer): AppContainer's properties are all `let`
    // by convention, but trustTier is mutable across the lifetime of a session (heartbeat
    // responses can downgrade/upgrade it). A `@MainActor final class` gives reference semantics
    // + main-actor isolation for safe concurrent reads during UIKit render paths.
    //
    // Thread safety: all reads + writes MUST occur on the main actor. Plan 07 SceneDelegate
    // helper is @MainActor; Plan 08 banner render is @MainActor; AppContainer.init is @MainActor.
    //
    // Lifetime: one AppSession instance per AppContainer. Logout (SESS-04) does NOT mutate
    // AppSession — the container itself is discarded (or swapped) on logout per Phase 3 pattern.

    import Foundation

    @MainActor
    public final class AppSession {
        /// Server-returned trust tier. Default is .softwareOnly (safe default — banner shows
        /// until backend confirms .hardwareAttested). Set on every /device/register + /device/heartbeat
        /// response (D-12).
        public var trustTier: TrustTier

        public init(trustTier: TrustTier = .softwareOnly) {
            self.trustTier = trustTier
        }
    }
    ```

    Note: If AppContainer already has a session-holder type (e.g., `SessionState` or similar), investigate first and extend that instead of creating a sibling class. Read AppContainer.swift before creating to confirm no naming collision. If a holder exists but is not main-actor-isolated, ADD `trustTier` to it and update `@MainActor` annotations rather than creating a new file. If no holder exists, the file above lands as new.

    The default `.softwareOnly` value is deliberate — until the first /device/register response lands, the client treats itself as untrusted (and the LimitedTrustBanner in Plan 08 renders). Once the backend confirms `.hardwareAttested`, the banner disappears. This is the safe direction of ambiguity: a brief over-showing of the banner is preferable to ever missing the banner when the backend actually said softwareOnly.
