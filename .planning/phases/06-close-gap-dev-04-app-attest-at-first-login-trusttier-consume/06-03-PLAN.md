<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| iOS process → Keychain | `device.trustTier` (seed read) and `session.kycStatus` (refresh write) cross here. |
| backend → client (`GET /kyc/status` response) | `overall_status` is untrusted wire input; decoded by a typed endpoint, then cached to Keychain. |
| Release vs DEBUG build surface | Deleting `uiTestTrustTierOverride` removes a DEBUG seam — relevant to what ships in Release. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03-01 | Elevation of Privilege / Tampering | `uiTestTrustTierOverride` DEBUG static could, if ever compiled into Release, forge `trustTier` and suppress the limited-trust banner | mitigate | D6-03 — the seam is DELETED entirely at all 3 sites (strictly better than the prior `#if DEBUG`-gated state). The remaining `-MockOTPTrustTierForUITest` launch arg is parsed only inside `#if DEBUG` blocks (Release compiles to zero bytes). `grep` for the symbol must return 0. |
| T-06-03-02 | Tampering | A client-tampered `device.trustTier` Keychain seed suppressing the banner | accept | `trustTier` is backend-driven (Phase 4 D-12); the item is only written from a `/device/register` response; `.afterFirstUnlockThisDeviceOnly` Keychain items are not user-editable on a non-jailbroken device; the banner is informational, not a gate (Phase 4 D-11). |
| T-06-03-03 | (Correctness — fail-closed integrity) | Stale `kycStatus` causing a fail-closed cold-boot misroute (WARNING-1) | mitigate | D6-08 — `kycStatus` is refreshed after a successful `GET /kyc/status`. The fix PRESERVES fail-closed semantics (any non-"verified"/absent value → KYC gate); it never routes to the role shell on a stale/absent value. Verified by tests for both verified and non-verified fetches. |
| T-06-03-04 | Information Disclosure | `kycStatus` written to insecure storage | mitigate | The refresh write uses Keychain `.kycStatus` with `.afterFirstUnlockThisDeviceOnly` — never `UserDefaults` or a plain file (CLAUDE.md / SEC-03). The value is a controlled-vocabulary status string (no PII). |
| T-06-03-05 | Spoofing | The observable-trustTier notification/closure spoofed to flip the banner | accept | The observation mechanism is an in-process `Notification.Name` post or a closure — only in-process code can fire it, and `trustTier` mutation itself is gated to the heartbeat / first-login consumer. Cross-process spoofing of an in-process notification is not a realistic vector on iOS. |
| T-06-03-SC | Tampering | npm/pip/cargo installs | mitigate | N/A — Phase 6 installs zero packages (06-RESEARCH Package Legitimacy Audit: not applicable). No package-manager install tasks in this plan. |
</threat_model>
