    **Step C — Modify `validationLedger/App/AppCoordinator.swift` to fill .auth + .anotherActiveSession:**

    Locate `makeRoot(for:)` (lines ~41-55). Read the existing static-vs-instance shape — Phase 1 has `Self.makeRoot(for:)` taking only `phase`. Phase 3 needs the container available; either:
    - (a) Make `makeRoot(for:container:)` an instance method that uses `self.container` (refactor)
    - (b) Pass container in: `Self.makeRoot(for: phase, container: container)`

    The PATTERNS.md recommendation (lines 941-970) is option (b). Apply it:

    ```swift
    private static func makeRoot(for phase: AppPhase, container: AppContainer) -> UIViewController {
        switch phase {
        case .launch:
            return ShipperTabBarController()  // unchanged Phase 1
        case .auth:
            // Phase 3 D-01:
            let coord = AuthCoordinator(container: container)
            // The closure capture below introduces a retain cycle if the AuthCoordinator
            // is held by AppCoordinator instance and also captures self. Fix: hold
            // AuthCoordinator weakly OR have the closure not retain self.
            // For the static-method path, the AppCoordinator instance receiving the
            // role callback comes from the captured scope. SceneDelegate observer
            // re-presents on .roleResolved equivalent — so onAuthenticated forwards
            // to a Notification (already wired in Phase 1?), OR to a property on
            // AppCoordinator.
            //
            // Simplest: post a Notification that SceneDelegate observes:
            coord.onAuthenticated = { role in
                NotificationCenter.default.post(
                    name: .authResolved,
                    object: nil,
                    userInfo: ["role": role.rawValue]
                )
            }
            // Hold strongly via a static dictionary or instance property — needed
            // because nav controller is the rootViewController; the coordinator must
            // outlive its lifetime. SceneDelegate wraps the AppCoordinator in a
            // strong ref already (Phase 1). To keep AuthCoordinator alive, store on
            // AppCoordinator instance — refactor makeRoot to instance.
            return coord.rootViewController
        case .role(let role):
            return AppCoordinator.roleCoordinator(for: role)  // existing Phase 1
        case .anotherActiveSession:
            return AnotherActiveSessionViewController(supportEmail: container.env.supportEmail)
        }
    }
    ```

    **Coordinator retention strategy:** AuthCoordinator owns a UINavigationController. UIKit's view-controller lifecycle keeps the nav alive via `window.rootViewController`. The AuthCoordinator instance, however, is held only by the closure `onAuthenticated`. Three options:

    1. **Static-property holder:** AuthCoordinator self-registers in a static `private static var current: AuthCoordinator?` set on init; cleared on completion.
    2. **AppCoordinator instance property:** Refactor makeRoot to instance method; store `private var authCoordinator: AuthCoordinator?`.
    3. **Notification-based bubble:** AuthCoordinator posts `.authResolved` notification with role; SceneDelegate observes and root-swaps. AuthCoordinator can deinit naturally.

    Option 3 is the cleanest — symmetric with the existing `.sessionDidInvalidate` pattern. Use option 3.

    Implementation:
    - Add `extension Notification.Name { static let authResolved = Notification.Name("validationLedger.authResolved") }`
    - SceneDelegate observes `.authResolved` (alongside `.sessionDidInvalidate`); on fire, reads `userInfo["role"]` as String, constructs `Role(rawValue:)`, calls `presentRoot(.role(role))`. The AuthCoordinator's UINavigationController is then released because window.rootViewController = new instance.
