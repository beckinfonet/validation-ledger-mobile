    **Add `parseRetryAfter` as a private static method** on APIClient (anywhere in the file — recommended: at the bottom, before the closing brace, OR in an extension at the bottom of the file). Implementation per RESEARCH §iOS API #4:

    ```swift
    extension APIClient {
        /// Parses an HTTP `Retry-After` header. Returns nil if the header is
        /// missing or malformed. Both formats supported per RFC 7231:
        /// - Delta-seconds: "Retry-After: 60"
        /// - HTTP-date: "Retry-After: Wed, 21 Oct 2026 07:28:00 GMT"
        static func parseRetryAfter(from response: HTTPURLResponse, now: Date = .now) -> TimeInterval? {
            guard let raw = response.value(forHTTPHeaderField: "Retry-After") else {
                return nil
            }
            // Delta-seconds (integer) — most common form for rate-limit responses.
            if let seconds = TimeInterval(raw) {
                return max(0, seconds)
            }
            // HTTP-date fallback.
            let formatter = DateFormatter()
            formatter.locale = Locale(identifier: "en_US_POSIX")
            formatter.timeZone = TimeZone(identifier: "GMT")
            formatter.dateFormat = "EEE, dd MMM yyyy HH:mm:ss zzz"
            if let date = formatter.date(from: raw) {
                return max(0, date.timeIntervalSince(now))
            }
            return nil
        }
    }
    ```

    The `now: Date = .now` parameter is for testability — Test 3 can pass a fixed `now` to make HTTP-date assertions deterministic. (Production callers always pass the default.)

|----------|-------------|
| backend ↔ iOS app (HTTP transport) | Backend is the rate-limit authority; iOS surfaces the countdown faithfully but never enforces locally. |
| HTTPURLResponse ↔ NetworkError | Header-parsing happens at the boundary so endpoint code sees a typed error, never a raw status code. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-03-05-01 | Spoofing — OTP brute force | /auth/otp/verify endpoint | mitigate | Backend enforces rate limit + returns 429 + Retry-After. iOS APIClient parses both the status and the header into typed `NetworkError.rateLimited(retryAfter:)`; OTPViewModel (Plan 09) disables Verify button for the duration.
