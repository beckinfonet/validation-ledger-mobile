> Visual and interaction contract for the **Chain-of-Vouches Redesign** phase — replaces the Phase 9 iPhone 2D `TrustGraphView` with two top-anchored components (`EveryoneOnLoadStripView` + `ChainOfVouchesView`) and a new shared `RoleAvatarView` primitive. Preserves the Phase 9 iPad `TrustGraphView` contract unchanged. Generated by gsd-ui-researcher, verified downstream by gsd-ui-checker.
>
> **Platform note:** Native iOS UIKit client (iPhone + iPad, iOS 17+). The shadcn initialization gate and component-registry safety gate are **not applicable** — no `components.json`, no Tailwind, no React. The "Design System" section describes the existing in-repo UIKit token layer (`validationLedger/UI/DesignSystem/`).
>
> **Phase frame** (orchestrator-supplied): 12 SPEC requirements locked (R1–R12). The screen this UI-SPEC binds is **iPhone Load Detail above the body** (status timeline + freight rows below). iPad regular-width is the Phase 9 contract verbatim — this document only extends iPad where R10 / R4 require it (footer pill component reuse + snapshot baseline re-record).

## UIKit vs SwiftUI Decision (locked — inherited from Phase 9)

**Decision: UIKit, programmatic, no XIB / Storyboard.**

The chain-of-vouches surface is a marquee fraud-signaling surface — the same class of "critical UI" CLAUDE.md reserves for UIKit. Every Phase 9 rationale carries forward: gesture and selection arbitration on the strip (D-08 chip tap → tree scroll + highlight) needs deterministic recognizer ownership; the brief chip-tap highlight animation is `UIView.animate` keyframe-class control; the `VerificationBadgeView` reuse from Phase 8 is UIKit. The new components conform to the same UIKit-only contract as every shipped v1.0 + v1.1 surface.

- **View controllers:** `LoadDetailViewController` is MODIFIED (size-class routing point per R5); no new view controllers are introduced. The chip-tap → tree-scroll wiring lives on the VC, not the VM (D-09 — role selection is a UI concern, not a state-machine concern).
- **New views (all `UIView` subclasses):** `RoleAvatarView` (`UI/Components/`), `EveryoneOnLoadStripView` (`Features/Loads/Detail/`), `ChainOfVouchesView` (`Features/Loads/Detail/`). All programmatic constructors, `required init?(coder:)` traps. ARCH-04.
- **Modal sheets:** None new — 9.1 does not introduce tap-on-tree-row → verification-basis sheet (deferred per CONTEXT.md). Phase 9 `VerificationBasisSheetViewController` + `HandoffDetailSheetViewController` remain on iPad only.
- **Pull-to-refresh:** NOT present on the detail screen (Phase 9 contract preserved).

### Per-Role Avatar Palette (DS.Colors.Roles)

Locked from the reference photo. All values are iOS system colors so dark mode + dynamic-range adapt automatically (CLAUDE.md mandate).

| Role | `Role` enum case | Avatar circle fill | Abbrev (3 letters, uppercase) |
|------|------------------|--------------------|-----------------------------|
| Shipper   | `.shipper`   | `.systemBlue`   | `SHP` |
| Broker    | `.broker`    | `.systemOrange` | `BRK` |
| Carrier   | `.carrier`   | `.systemGreen`  | `CAR` |
| Dispatch  | `.dispatch`  | `.systemPurple` | `DSP` |
| Factoring | `.factoring` | `.systemTeal`   | `FCT` |

> Rationale for `.systemTeal` on Factoring (vs. the reference photo's "blue"): the reference's Factoring chip color is close enough to the Shipper chip to read as the same role at iPhone widths — a fraud-readability problem the redesign exists to eliminate. `.systemTeal` is hue-distinct from `.systemBlue` (shipper) under both light and dark mode and remains in the "cool / trustworthy" half of the palette appropriate for a financial role. Deferred refinement after a11y-contrast review is captured in CONTEXT.md `<deferred>`.

The 3-letter abbreviations are uppercase, San Francisco rounded weight semibold (see Typography), centered. They are NOT derived at runtime from `Role.rawValue` — they are a literal `switch role` inside `RoleAvatarView` so the canonical "BRK" never drifts to "BRO" or "BROK" if the enum case name changes. A unit test asserts each abbreviation literal.

## Spacing Scale

Declared values (must be multiples of 4) — INHERITED from `DS.Spacing` (Phase 1 token layer):

| Token | Value | Usage in 9.1 |
|-------|-------|-------|
| `xs`  | 4px  | Status-dot stroke; chip avatar-to-text inline padding |
| `sm`  | 8px  | Inter-chip spacing in the strip; tree row inner inline gap (avatar → role-name) |
| `md`  | 16px | Default element padding; card horizontal inset; tree-row vertical gap |
| `lg`  | 24px | Card vertical padding (top + bottom); strip-to-card vertical gap |
| `xl`  | 32px | Card-to-status-timeline vertical gap (R8 scroll-order separation) |
| `xxl` | 48px | (not used in 9.1; reserved for major section breaks) |

**Exceptions:**

- **44pt minimum touch target** on every interactive surface: each strip chip (D-08) honors a `widthAnchor.constraint(greaterThanOrEqualToConstant: 44)` + `heightAnchor.constraint(greaterThanOrEqualToConstant: 44)`. The 44pt floor is a UI-SPEC universal documented in CONTEXT.md "Established Patterns"; this UI-SPEC re-asserts it for the chip tap target specifically. The chip's *visual* circle is smaller (see Component Geometry below), but its *hit-test* surface is at least 44×44pt via padding.
- **Avatar circle diameters** (non-multiples of 4 are forbidden):
  - Strip chip avatar: **40pt** diameter (so the 44pt hit-test is met with a 2pt padding ring; matches the reference photo proportions).
  - Tree row avatar: **32pt** diameter (smaller — rows are read in vertical sequence; the avatar is a quick-scan anchor, not a tap target since rows are non-interactive in 9.1).
  - Status dot on avatar (bottom-right): **12pt** diameter on the 40pt strip avatar; **10pt** on the 32pt tree avatar. Status-dot border: 2pt stroke in `DS.Colors.background` (matches the avatar's parent surface, creating the "punched-out" visual the reference shows).

## Typography

INHERITED from `DS.Typography` (Phase 1 token layer; Dynamic Type-aware). 9.1 declares which existing token each new label binds to. **No new typography tokens are introduced.**

| Role | Token | Resolves to (preferred-font) | Weight | Used in 9.1 for |
|------|------|------|--------|-----------------|
| Body      | `DS.Typography.body`     | `.body`     | regular | Tree row `displayName`; card subtitle paragraph |
| Heading   | `DS.Typography.headline` | `.headline` | semibold | Card title ("Chain of vouches"); tree row role name ("Shipper", "Broker", …) |
| Label     | `DS.Typography.footnote` | `.footnote` | regular | "VIA SHP" attribution suffix; footer pill copy; strip "All watching live · tap for details" caption |
| Display   | `DS.Typography.title2`   | `.title2`   | semibold | (NOT used in 9.1 — Phase 9 owns this for the pinned summary header above the chain block) |
| Avatar    | `DS.Typography.footnote` w/ `UIFontDescriptor.SymbolicTraits.traitBold` applied | `.footnote` bold | semibold | The 3-letter avatar abbreviation (`SHP`, `BRK`, …). Cast to `.semibold` via `UIFont.systemFont(ofSize: footnote.pointSize, weight: .semibold)` so the abbreviation reads tight inside the avatar circle. |

**Line heights:**

- All labels use `UILabel`'s default line height for the bound text style (system-computed; iOS-native).
- The card subtitle paragraph (2 lines max) sets `numberOfLines = 2` and `lineBreakMode = .byTruncatingTail`; the system line-height for `.body` is used (no manual override).
- Tree row `displayName` is a single line with `lineBreakMode = .byTruncatingTail`. Long party names (e.g. "Global Exports Logistics International") truncate; the full name is in the `accessibilityLabel` (R6).

**Weight discipline (2 weights only, per UI-SPEC universal rule):**

- **Regular** (`.regular`) — body, label/caption, subtitle paragraph, "VIA X" attribution suffix.
- **Semibold** (`.semibold`) — card title, tree row role name, avatar abbreviation, footer pill copy.

No other weight is permitted. Dynamic Type scales both weights identically.

## Color

Built on `DS.Colors`. The 60/30/10 rule applies to non-fraud-signal surfaces — the fraud-signal color (chain-compromised red, flagged red) deliberately breaks the 10% rule because the entire premise of the screen is that fraud signaling MUST dominate when the chain is compromised.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `DS.Colors.background` (`.systemBackground`) | The scroll view background; the area outside the chain-of-vouches card. |
| Secondary (30%) | `DS.Colors.surface` (`.secondarySystemBackground`) | The chain-of-vouches card fill (mid-tier surface — visually distinct from page background, holds the tree); the strip's chip background ring (the 44pt hit-test padding ring on the chip — same surface as the card; reads as "all in the same surface family"). |
| Accent (10%) | `DS.Colors.primary` (`.systemBlue`) | **Reserved-for list (explicit):** (1) the chip-tap highlight outline on a strip chip (D-08; 2pt stroke, animated fade in 120ms + fade out 200ms after the row scrolls into view); (2) the chip-tap highlight outline on the matching tree row(s) — same 2pt stroke, same fade timing; (3) the Shipper avatar circle fill (per `DS.Colors.Roles`). The chip-tap highlight is the ONLY interactive-state accent on the screen. |
| Destructive | `DS.Colors.destructive` (`.systemRed`) | Footer pill background tint when `chainIntegrity.verdict == .compromised`; flagged-state verification dot color (via `DS.Colors.Verification.color(for: .flagged)`). |

**Accent reserved for:** (1) Shipper avatar fill (palette choice — fixed per `DS.Colors.Roles`); (2) chip-tap highlight outline (interaction state — fade-in 120ms, fade-out 200ms with a 1.8-second hold; sticky until another chip is tapped, then the new chip takes selection). NEVER used for: tree row backgrounds, card chrome, footer pill (footer pill uses verdict-tier colors below), VIA-attribution text color (uses `DS.Colors.labelSecondary`).

**Footer pill verdict-tier colors (R4 — footer pill folded into card; mirrors Phase 9 `ChainIntegrityBannerView` palette):**

| Verdict (`ChainIntegrity.Verdict`) | Pill background | Icon + label foreground | SF Symbol |
|------------------------------------|------------------|----------------------|-----------|
| `.clean`       | `.systemGreen.withAlphaComponent(0.18)` | `.systemGreen` (label + icon) | `checkmark.seal.fill` |
| `.caution`     | `DS.Colors.caution` (`.systemYellow`)   | `.label` (label + icon) — yellow needs dark text per WCAG | `exclamationmark.triangle.fill` |
| `.compromised` | `DS.Colors.destructive` (`.systemRed`)  | `.white` (label + icon) — red needs white text | `exclamationmark.octagon.fill` |

> The `.clean` tint is NEW in 9.1 — Phase 9's `ChainIntegrityBannerView` short-circuits to `isHidden = true` on `.clean`, but the folded footer pill (R4) MUST render on every verdict (including clean) because the reference design's "✓ Chain intact · 4 vouches, no anonymous parties" cadence is the affirmative trust signal — a missing pill would read as "no signal," which is the opposite of the intended UX. The `.systemGreen.withAlphaComponent(0.18)` is a soft-tint that doesn't compete with the chain-compromised red — it reads as confirmation, not as a status banner. Hard contrast checked: `systemGreen` foreground on `systemGreen @ 0.18` over `secondarySystemBackground` passes WCAG AA at `.headline` size.

## Accessibility Contract (R6)

The Phase 9 iPad D-22 model (container with ordered `accessibilityElements`) is preserved verbatim on iPad regular-width. iPhone moves to a **leaf-element model**:

- `EveryoneOnLoadStripView` container: `isAccessibilityElement = false`. Each chip is its own leaf with `accessibilityTraits = [.button, .staticText]`, composed label `"<RoleDisplayName>, <VerificationStateCopy>"`.
- `ChainOfVouchesView` card: `isAccessibilityElement = false`. The eyebrow + title + subtitle are individual leaves (in scroll order: eyebrow, title, subtitle). Each tree row is a single leaf with `accessibilityTraits = .staticText`, composed label `"<RoleDisplayName> <displayName>, vouched by <ParentRoleDisplayName> <ParentDisplayName>, <VerificationStateCopy>"`. The footer pill is a single leaf, `accessibilityTraits = .staticText`, composed label `"Chain integrity: <VerdictSpoken>. <reason>"`.
- VoiceOver traversal order on iPhone: pinned-summary leaves → strip chips (in canonical role order, NOT scroll order if the user has scrolled the strip — the canonical order is the stable read order; this matches the visual layout from the canonical role hierarchy) → eyebrow → title → subtitle → tree rows (in role-hierarchy depth-first order: SHP → BRK → CAR → DSP → FCT, with siblings ordered by `node.partyID` alphabetical for determinism) → footer pill → status-timeline leaves → body-row leaves.
- VerificationState spoken copy (locked):
  - `.verified` → `"verified"`
  - `.pending` → `"verification pending"`
  - `.unverified` → `"not verified"` (T-08-06 literal "not" prefix — locked; mirrors Phase 8 `VerificationBadgeView.swift` line 202)
  - `.flagged` → `"flagged"`
- VoiceOver-traversable acceptance test: `ChainOfVouchesViewAccessibilityTests` asserts each chip + each row + the footer pill exposes the composed label for the 5 representative fixtures. The existing Phase 9 D-22 accessibility tests on iPad remain green.
- Dynamic Type: all labels set `adjustsFontForContentSizeCategory = true`. SF Symbols in the footer pill use `UIImage.SymbolConfiguration(textStyle: .footnote)` + `adjustsImageSizeForAccessibilityContentSizeCategory = true` (CR-03 precedent). Avatar abbreviations DO NOT scale (the 3-letter avatar abbreviation is locked to its avatar circle geometry; scaling it would either overflow the circle or shrink the circle to a dot at large content sizes — deferred per CONTEXT.md `<deferred>` "Avatar circle size scaling with Dynamic Type"). The avatar abbreviation's font is `UIFont.systemFont(ofSize: 11, weight: .semibold)` — a literal point size, NOT Dynamic Type — and a comment in `RoleAvatarView` documents this deliberate exception with a link back to the deferred-item entry.

- **TRUST-02 single-source-of-truth lock** — R12 + D-01–D-04. Negative-grep gate asserts `switch …VerificationState` mapping to a `UIColor` appears in exactly ONE file (`Colors.swift`). Both `RoleAvatarView` and `VerificationBadgeView` consume `DS.Colors.Verification.color(for: state)`.

(`Role` is also frozen by extension — the role-hierarchy parent table is a UI-layer convention.)
