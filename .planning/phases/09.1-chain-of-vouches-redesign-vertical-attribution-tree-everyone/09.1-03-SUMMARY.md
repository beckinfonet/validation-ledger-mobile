## Decisions Made

- **`ChipView` is a private nested class on `EveryoneOnLoadStripView`, not a peer file.** Rationale: the chip exists only in the context of the strip — there is no second consumer. Nesting keeps the public surface of the file at one type. The `@testable` introspection still works because internal access on the chip's properties is visible to the test target. A separate file would have required publishing the ChipView surface API.
- **Internal-access subview properties for `@testable` introspection.** `captionLabel`, `chips` array, `ChipView` class itself, and `ChipView.role/displayName/state/onTap` are all internal-access (no explicit `private`) so the unit-test target can iterate via `@testable import` without re-engineering test seams. Mirrors Plan 02 `RoleAvatarView`'s `let abbreviationLabel: UILabel` / `let statusDot: UIView` precedent.
- **Multi-node "multiple parties" literal as the planner-default per B1.** UI-SPEC does not lock a multi-node displayName at any line; the plan's `<action>` explicitly authorized the planner default. The localized value `loads.detail.chain.9_1.strip.chip.multi_node_displayname` = `"multiple parties"` is a single trivially-changeable string if product later wants `"multiple brokers"` / `"several parties"` / etc.
- **Most-suspicious-wins implemented as a private static rank + `states.max(by:)` aggregation, not a public API.** The suspicion ordering is a presentation aggregation, not a domain rule (T-09.1-04 mitigation: the ranking does not leak into the data layer or the test surface). The rank function is internal to the strip's compilation unit.
- **TRUST-02 strict-grep gate (R12) sees NO new consumer in this plan.** The strip does NOT call `DS.Colors.Verification.color(for:)` directly — it composes `RoleAvatarView(.strip)`, which in turn calls the helper. This is the intended composition pattern: primitives consume the helper, feature views consume the primitives. The R12 expected-consumer set stays at exactly 2 files post-Plan-03.
- **Acceptance grep #5 (`composeAccessibilityLabel(role:displayName:state:)` regex) required a Swift method-reference form in the doc comment.** The actual function declaration uses standard parameter syntax `(role: Role, displayName: String, state: VerificationState)`. The regex was intentionally written to match the Swift method-reference form, locking the parameter-label-set rather than the call-site convention. The doc comment line `/// Method reference: \`composeAccessibilityLabel(role:displayName:state:)\`` satisfies the gate without changing semantic behavior.
- **Spoken verification-state vocabulary lives in 4 separate `NSLocalizedString` keys.** Each speakable form is a distinct translation unit. Collapsing to a single key returning a literal would make the LOCKED T-08-06 `"not verified"` prefix harder to localize in v2 (where the `"not"` prefix may need to land elsewhere in the sentence per the target language's grammar). The 4-key shape also matches `ChainIntegrityBannerView.swift`'s per-verdict spoken-key precedent.
- **Snapshot test methods are 10 explicit per-cell functions (vs. a parameterized loop).** Mirrors Plan 02 Pattern 6: discrete CI test names make a failing cell unambiguous in the Xcode test navigator (e.g. `test_VL_1009_iPhoneSE3Portrait_rendersExpected` is unambiguous when one cell breaks). A parameterized loop would collapse 10 cells into a single failing test name.
- **Snapshot trait-override Dynamic Type tier is `.large` (not `.accessibilityExtraExtraExtraLarge`).** Plan 03's UI-SPEC matrix specifies 5 fixtures × 2 widths = 10 cells; it does NOT call for the 12-fingerprint matrix (3 verdicts × 2 devices × 2 DT sizes) the Phase 9 trust-graph snapshot suite uses. `.large` is the default content size category appropriate for the iPhone 15 / SE 3 portrait fingerprint pair.
- **Trailing caption is right-aligned + non-compressible.** `textAlignment = .right`, `setContentCompressionResistancePriority(.required, for: .horizontal)`, `setContentHuggingPriority(.required, for: .horizontal)`. Guarantees the caption never gets compressed even when the scroll view's chip stack wants all the space — the scroll view scrolls instead. The horizontal scroll view's trailing-anchor constraint to `captionLabel.leadingAnchor` enforces the spatial precedence.
