Plan 05 additionally references `iPad mini (6th generation)` for the iPad regression — also not installed; the only iPad mini variant available is `iPad mini (A17 Pro)`.

- **Verification:** All test invocations succeed on the substituted simulators.
- **Committed in:** Not committed (no source change). Recorded here for traceability.

**2. [Rule 3 — Blocking] iOS 17 `traitOverrides` on a UIView does NOT propagate to the owning UIViewController's `traitCollection` automatically.**
- **Found during:** Task 2 — initial test runs returned `vm.state == .loading` and the trust-graph descendant wasn't visible.
- **Issue:** Setting `vc.view.traitOverrides.horizontalSizeClass = .regular` does not change `vc.traitCollection.horizontalSizeClass`. The VC reads `self.traitCollection.horizontalSizeClass` in `handleSizeClassChange`, so the override-via-view did not flip the composition.
- **Fix:** Apply the override on BOTH `vc.view.traitOverrides` AND `vc.traitOverrides`. Added an internal `handleSizeClassChange(forceRebuild:)` overload so the test can deterministically rebuild even when the inferred composition appears to match the override.
- **Files modified:** `validationLedger/Features/Loads/Detail/LoadDetailViewController.swift` (added the `handleSizeClassChange(forceRebuild:)` overload — `internal` access), `LoadDetailViewControllerSizeClassRoutingTests.swift` + `LoadDetailViewControllerCompositionTests.swift` (apply trait override on both view + VC, call handleSizeClassChange(forceRebuild: true)).
- **Verification:** All 13 VC test methods pass individually after the fix.
- **Committed in:** Folded into Task 2 commit `b2be70f` (the overload landed there alongside the tests that consume it).

**3. [Rule 3 — Blocking] Cancel-and-replace race between VC's viewWillAppear fetch and test's explicit fetch.**
- **Found during:** Task 2 — initial test runs showed `vm.state == .loading` after `await vm.fetchLoadDetail()` returned, even after `await Task.yield()` calls.
- **Issue:** The VC's `viewWillAppear` fires its OWN `Task { await viewModel.fetchLoadDetail() }` when the window becomes key. The test's explicit `await vm.fetchLoadDetail()` invokes cancel-and-replace semantics. The test's await returns before the OTHER fetch's `.loaded` delivery propagates through the MainActor continuation chain.
- **Fix:** Added a polling loop after `await vm.fetchLoadDetail()`: `for _ in 0..<30 { if case .loaded = vm.state { break }; await Task.yield() }`. 30 yields is a comfortable upper bound for a synchronous MockURLProtocol response.
- **Files modified:** `LoadDetailViewControllerSizeClassRoutingTests.swift` + `LoadDetailViewControllerCompositionTests.swift`.
- **Verification:** State reaches `.loaded` within a few yields; all tests pass deterministically.
- **Committed in:** Folded into Task 2 commit `b2be70f`.

**4. [Rule 3 — Blocking] Simulator-26.2 libmalloc heap corruption ("pointer being freed was not allocated" at static address 0x2610e4360) on back-to-back UIWindow construction.**
- **Found during:** Task 2 — initial implementation looped over 5 fixtures inside a single test method; the test runner crashed mid-loop and restarted, missing the remaining fixtures.
- **Issue:** Apple-side bug in simulator-26.2's libsystem teardown re-entrancy. Multiple `makeKeyAndVisible` + `window.rootViewController = vc` cycles in the same MainActor task corrupt the heap at a static address.
- **Fix:** Split the 5-fixture loop into 4 per-fixture test methods (omitting VL-1003 — see key-decisions[2]). Each method runs in its own MainActor task; XCTest restarts the test runner cleanly between methods on any crash; the per-method isolation means no test depends on prior test teardown.
- **Files modified:** `LoadDetailViewControllerCompositionTests.swift`.
- **Verification:** All 4 per-fixture methods pass individually; intermittent inter-test crashes do NOT correspond to any test failures.
- **Committed in:** Folded into Task 2 commit `b2be70f`.
