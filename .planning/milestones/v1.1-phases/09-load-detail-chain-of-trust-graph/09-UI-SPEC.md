# Phase 9 — UI Design Contract

> Visual and interaction contract for the **Load Detail & Chain-of-Trust Graph** phase — the marquee surface of the entire v1.1 milestone. Generated by gsd-ui-researcher, verified downstream by gsd-ui-checker.
>
> **Platform note:** Native iOS UIKit client (iPhone + iPad, iOS 17+). The shadcn initialization gate and component-registry safety gate are **not applicable** — no `components.json`, no Tailwind, no React. The "Design System" section describes the existing in-repo UIKit token layer (`validationLedger/UI/DesignSystem/`).
>
> **Phase 9 frame** (orchestrator-supplied): The marquee surface of v1.1 — load detail with a status timeline and an interactive shipper→broker→carrier→dispatch→factoring trust graph; tap a node for verification basis, tap an edge for handoff detail. Six requirements: LOAD-05, LOAD-06, TRUST-01, TRUST-03, TRUST-04, TRUST-05. **The trust graph IS the screen** — this entire spec is organised so every design tradeoff resolves in favor of the graph's polish.

## UIKit vs SwiftUI Decision (locked)

**Decision: UIKit, programmatic, no XIB / Storyboard.**

CLAUDE.md permits SwiftUI only for "non-critical surfaces like Settings/static lists." The load detail screen + chain-of-trust graph is the **marquee surface of the entire v1.1 milestone** — the place users will look first on every load for the fraud signal — and the rendering approach is already ratified by research (custom UIKit `UIView` nodes + `CAShapeLayer` edges, zero new dependencies). SwiftUI here would:

- Force the gesture-arbitration model (pinch zoom + double-tap recenter + single-tap node + single-tap edge — D-04) onto SwiftUI's gesture system where conflict resolution between simultaneous recognizers is opaque.
- Force the pulse animation (D-15 compromised tier) onto a `withAnimation` repeating modifier where CAShapeLayer-grade halo control is unavailable.
- Force a `UIViewRepresentable` wrap around any UIKit gesture or CALayer reuse — silently importing the SwiftUI ↔ UIKit interop seam exactly where the fraud signal must be highest-polish.
- Re-implement the Phase 8 `VerificationBadgeView` + `LoadStatusBadgeView` as `UIViewRepresentable` wrappers, defeating the entire TRUST-02 reuse story.

Every shipped v1.0 + v1.1 surface to date is UIKit. Phase 9 continues the precedent without exception.

- **View controllers:** subclasses of `UIViewController`. Phase 9 introduces `LoadDetailViewController`, `VerificationBasisSheetViewController`, `HandoffDetailSheetViewController`. Pushed via the existing `RoleCoordinator` navigation stack (or a thin new `LoadDetailCoordinator` — planner discretion per CONTEXT § Claude's Discretion).
- **Graph canvas:** custom `TrustGraphView: UIView` containing one `TrustNodeView: UIView` per `TrustNode` and one `CAShapeLayer` per `TrustEdge`, hosted inside a `UIScrollView` for pan + pinch.
- **Body composition:** an outer `UIScrollView` (iPhone) or a `UIStackView` branching on `traitCollection.horizontalSizeClass` (iPad regular → side-by-side split). Inside the body, `UIStackView`-in-`UIScrollView` is preferred over `UICollectionView` because the body is a short, non-mutating list (timeline + freight rows + parties + verdict block). Planner has discretion to switch to `UICollectionViewListCell` if the row catalog grows.
- **Modal sheets:** `UISheetPresentationController` with `.medium` + `.large` detents (iOS 17+ native). One presentation infrastructure for both node-tap (TRUST-03) and edge-tap (TRUST-04).
- **Pull-to-refresh:** **NOT present on the detail screen.** The detail screen is a one-shot fetch on appear per CONTEXT § Deferred. (LOAD-08's pull-to-refresh lives only on the list.)

### New token additions (additive only — no rename)

Phase 9 adds **one** new public color member to `DS.Colors` and reuses one existing system color under a new documented role:

| New token | Backing value | Phase 9 usage |
|-----------|---------------|---------------|
| `DS.Colors.caution` | `.systemYellow` | Chain-integrity banner background when `verdict == .caution`; yellow halo on caution-flagged nodes; yellow dashed-line color on caution-flagged edges. Parallels `LimitedTrustBannerView`'s caution semantic and the `.pending` verification-badge fill (which already uses `.systemYellow` directly) — Phase 9 promotes this to a named token to lock the meaning across surfaces. |

**No new SPACING or TYPOGRAPHY tokens.** Every spacing distance in the graph, the timeline, the sheets, and the body uses an existing `DS.Spacing` value. Every label uses an existing `DS.Typography` style.

## Screen Composition (the marquee posture)

Resolves CONTEXT D-01, D-02, D-03. The screen has three regions and two layouts (compact iPhone vs. regular iPad).

### iPhone (`horizontalSizeClass == .compact`)

```
┌─────────────────────────────────────┐
│ ◂ Back            Loads             │  ← Nav bar (system, "Loads" back chevron)
├─────────────────────────────────────┤
│ Pinned summary header (~60pt)       │  ← Reference # · origin→dest · LoadStatusBadgeView
├─────────────────────────────────────┤
│ [Chain-integrity banner — if !clean]│  ← Fixed (D-16), yellow or red, never scrolls away
├─────────────────────────────────────┤
│                                     │
│       T R U S T   G R A P H         │  ← ~60–70% of screen, dominant region
│                                     │      Hosts UIScrollView w/ min=1.0, max=2.5
│           [Node]                    │      Fit-all-nodes-tight default zoom (D-05)
│             │                       │      Pinch zoom + double-tap recenter (D-04)
│         [Node]──[Node]              │
│             │                       │
│           [Node]                    │
│                                     │
├═════════════════════════════════════┤  ← Scroll boundary — body scrolls beneath
│ Status timeline                     │  ← Horizontal stepper + current-state card (D-17)
│ ─●─●─●─◯─◯─◯─                       │
│ [Current state expanded card]       │
├─────────────────────────────────────┤
│ Freight detail rows                 │  ← Origin/destination, dates, equipment, weight, rate
├─────────────────────────────────────┤
│ Parties (inline list)               │  ← Each party row: VerificationBadgeView + role + name
├─────────────────────────────────────┤
│ Chain-integrity verdict block       │  ← Only when verdict != .clean
│ (same data as banner, scrollable)   │      Intentional duplication (D-16)
└─────────────────────────────────────┘
```

- The pinned summary header lives **above** the graph region and pins to `safeAreaLayoutGuide.topAnchor` of the view controller's view. It does NOT scroll.
- The chain-integrity banner (if rendered) sits between the pinned header and the graph region. It pins to the bottom of the header and the top of the graph region. It does NOT scroll (D-16). When the verdict is `.clean`, this view is absent (not collapsed-to-zero-height, but `isHidden = true` AND removed from any `UIStackView` arranged subviews to avoid invisible-height hit-test surfaces).
- The graph region is a fixed-height container. On iPhone its height is `view.safeAreaLayoutGuide.layoutFrame.height * 0.62` (rounded to whole points). This is the dominant 60–70% region. Below it, the body scrolls.
- The body below the graph is a single `UIScrollView` (the screen's primary scroll container). The pinned header + banner + graph live in a non-scrolling parent above the scroll view; the scroll view starts at the graph's bottom edge.

### iPad regular width (`horizontalSizeClass == .regular`)

```
┌──────────────────────────────────────────────────────────┐
│ ◂ Loads                           Load Detail            │
├──────────────────────────────────────────────────────────┤
│ [Banner if !clean — spans full width above split]        │  ← Banner is full-width above split
├────────────────────────────┬─────────────────────────────┤
│                            │ Pinned summary header       │
│                            ├─────────────────────────────┤
│         T R U S T          │ Status timeline             │
│         G R A P H          │ Freight detail rows         │
│       (left ~60%)          │ Parties (inline)            │
│       fit-all-tight        │ Chain-integrity verdict     │
│       pannable/zoomable    │   (only when !clean)        │
│                            │                             │
│                            │ (right ~40%, scrollable)    │
│                            │                             │
└────────────────────────────┴─────────────────────────────┘
```

- **Split ratio:** left pane = `0.60 * view.safeAreaLayoutGuide.layoutFrame.width`, right pane = `0.40 *`. (60/40 is the indicative ratio from CONTEXT D-03; pinned here as the contract value. Tested at iPad mini portrait — 0.40 of 744pt = ~297pt right pane, which clears the Apple HIG readable-width minimum.)
- **Banner placement:** the chain-integrity banner spans the **full width above the split** so the fraud signal is the topmost visual element on iPad as well. It is NOT inside the left graph pane.
- **Left pane (graph):** a single `TrustGraphView` filling the pane. Pinch zoom + pan are still active. The fit-all-nodes-tight default zoom recomputes for the wider pane (D-05) — same role-slot logic, rescaled into the available canvas (D-06; resolves spike item (d)).
- **Right pane (body):** the same bill-of-lading content as iPhone below-the-fold, plus the pinned summary header (which on iPhone lives above the graph; on iPad it moves into the top of the right pane).
- **Trait transitions:** `traitCollectionDidChange(_:)` rebuilds the layout. Rotation from compact → regular (iPhone Plus / Max landscape, iPad split-multitasking) animates the split into existence; the existing pinch-zoom state on the graph survives the rebuild (the `UIScrollView.zoomScale` is preserved across the layout change).

### Pinned summary header content

Both layouts. Single line on iPhone (truncates with ellipsis on overflow), single line on iPad right pane.

| Element | Style | Token |
|---------|-------|-------|
| Reference number ("VL-1023") | `.headline` 17pt semibold, `.label` color | `DS.Typography.headline` |
| Origin → destination ("Dallas, TX → Atlanta, GA") | `.body` 17pt regular, `.label` color | `DS.Typography.body` |
| `LoadStatusBadgeView` | per Phase 8 § Color status table (13-state, 3-tone neutral ramp) | reused as-is |

Arranged horizontally with `DS.Spacing.md` (16pt) leading/trailing safe-area padding, `DS.Spacing.sm` (8pt) interior spacing.

## Trust Graph Visual Language (the marquee region)

Resolves CONTEXT D-04 through D-16. This is the primary contract of Phase 9.

### Node visuals (`TrustNodeView`)

Each `TrustNode` renders as a single `TrustNodeView: UIView`. Composes the Phase 8 `VerificationBadgeView` plus role label plus display-name label inside a chrome container.

| Element | Spec |
|---------|------|
| Chrome shape | **Rounded square**, corner radius `12pt`. (Chosen over a circle because a circle leaves dead space and pushes the SF Symbol inside `VerificationBadgeView` off-center as Dynamic Type scales the label — a rounded square gives the badge + role + name three-line stack room without distortion.) |
| Chrome size at fit-all-tight zoom | Width = `min(80pt, paneWidth / 6)`, height = intrinsic content height. The graph layout engine snaps a uniform width to every node; height varies only with Dynamic Type. |
| Chrome background | `DS.Colors.surface` (`.secondarySystemBackground`) in `.clean` chain state; dimmed to 50% opacity in non-clean chain state when the node is NOT flagged (D-15). |
| Chrome border | `0.5pt` separator (`DS.Colors.separator`) — visible at fit-all-tight zoom; scales linearly with `UIScrollView.zoomScale`. |
| Internal padding | `DS.Spacing.sm` (8pt) on all four edges. |
| Internal stack | Vertical `UIStackView`, `.center` alignment, spacing `DS.Spacing.xs` (4pt). Three arranged subviews top-to-bottom: role label · `VerificationBadgeView` · display-name label. |
| Role label | `.caption1`-equivalent (`DS.Typography.caption`), uppercase, `DS.Colors.labelSecondary`, single line, e.g. "BROKER". |
| `VerificationBadgeView` | Phase 8 component reused verbatim. The 4-state color ramp (`.verified` blue / `.pending` yellow / `.unverified` neutral grey / `.flagged` red) is the per-node trust signal — **NOT** the same as the chain-level integrity halo (which is a *separate* CAShapeLayer drawn behind the chrome — see Halo below). A node can have a `.verified` badge and a `.compromised`-chain halo simultaneously; this is meaningful (the party itself is verified, but the chain it sits in is broken). |
| Display-name label | `.footnote` (`DS.Typography.footnote`), `.label` color, max 2 lines, centered, truncating-tail, e.g. "Acme Brokerage". |
| Touch target | Whole node container is tappable; minimum hit area 44×44pt (Apple HIG). The chrome's intrinsic size at the smallest Dynamic Type setting + the `DS.Spacing.sm` interior padding ensures this without extra `heightAnchor.constraint(greaterThanOrEqualToConstant:)`, but the planner adds the explicit constraint defensively. |
| Tap behavior | Single-tap → `VerificationBasisSheetViewController` opens for this node (TRUST-03). Double-tap → graph recenters+zooms to this node (~250ms ease-in-out, scale `1.8x`). |

### Halo layer (chain-integrity flagged nodes)

A separate `CAShapeLayer` per flagged node, sibling-below the chrome `UIView` inside the `TrustGraphView`'s layer tree (drawn first, so the chrome paints over it). The halo is NOT a subview — it's a layer on the parent graph view, so its animation does not affect the node's own layout.

| Chain integrity | Halo |
|-----------------|------|
| `.clean` | None. No halo layer added. |
| `.caution` AND node's `partyID ∈ implicatedNodeIDs` | **Yellow halo** (`DS.Colors.caution`). Solid filled rounded-rect path, inset `-6pt` from the node's chrome frame (the halo bleeds outside the chrome by 6pt on every side), opacity `1.0`, no animation. |
| `.compromised` AND node's `partyID ∈ implicatedNodeIDs` | **Red halo** (`DS.Colors.destructive`). Same geometry as caution. Animated subtle pulse: opacity `0.6 → 1.0 → 0.6`, duration `1.2s`, `CAMediaTimingFunction(name: .easeInEaseOut)`, `repeatCount = .infinity`. The pulse is the marquee "this is BAD" tell (D-15). |

**Pulse-only-on-compromised invariant:** The pulse animation is added in code paths gated by `chainIntegrity.verdict == .compromised`. The caution halo NEVER pulses; the clean state has no halo at all. This is what makes the pulse a marquee signal — it appears only on the loudest fraud verdict, so users who see one know to investigate.

### Edge visuals (`CAShapeLayer` per `TrustEdge`)

Each edge is a `CAShapeLayer` drawn between two node centers on the `TrustGraphView`'s root layer. **NOT** a subview — a layer-only treatment is lighter and gives finer dashed-stroke control.

| Edge state | Stroke color | Stroke style | Width |
|------------|--------------|--------------|-------|
| Chain `.clean` (regardless of `relationshipState`) | `DS.Colors.separator` (`.separator`) | Solid | `2pt` at zoom 1.0; constant in screen space (scaled inversely with zoom) |
| Chain `.caution` AND `edgeID ∈ implicatedEdgeIDs` | `DS.Colors.caution` (`.systemYellow`) | **Dashed** — `lineDashPattern = [6, 4]` | `2pt` |
| Chain `.compromised` AND `edgeID ∈ implicatedEdgeIDs` | `DS.Colors.destructive` (`.systemRed`) | **Dashed** — `lineDashPattern = [6, 4]` | `2pt` |
| Non-implicated edge when chain `!= .clean` | `DS.Colors.separator` at 50% opacity (dimmed per D-15) | Solid | `2pt` |

**Edge tap target:** Each edge has an INVISIBLE companion `UIView` overlaid on the edge's path, sized to a `28pt` band centered on the line (the band gives a wider, more forgiving touch target around the `2pt` stroke; `28pt` is the smallest band that still satisfies a 44pt diagonal hit area at every realistic edge angle). The view is `accessibilityElement = true`, `isUserInteractionEnabled = true`, and carries a `UITapGestureRecognizer` that opens `HandoffDetailSheetViewController` (TRUST-04).

**Arrowheads:** Edges are directed (`fromPartyID` → `toPartyID`). Each `CAShapeLayer` paints an arrowhead at the `toPartyID` end — a `7pt × 7pt` filled triangle in the same color as the stroke. The arrow's geometry is recomputed in `TrustGraphView.layoutSubviews()` whenever node positions or zoom change.

### Banner (`ChainIntegrityBannerView`)

A new `UIView` subclass, file `validationLedger/Features/Loads/Detail/ChainIntegrityBannerView.swift`. Mirrors the file-shape of `LimitedTrustBannerView` (programmatic, DS-token-styled, per-state `NSLocalizedString`-backed `accessibilityLabel`).

| Element | Spec |
|---------|------|
| Background | `.clean` → not rendered. `.caution` → `DS.Colors.caution`. `.compromised` → `DS.Colors.destructive`. |
| Foreground (icon + text) | `.caution` → `.label` (yellow background needs dark text for contrast). `.compromised` → `.white`. |
| SF Symbol (leading) | `.caution` → `exclamationmark.triangle.fill`. `.compromised` → `exclamationmark.octagon.fill`. (The octagon is louder than the triangle; visual escalation parallels the color escalation.) |
| Text | `.footnote` (`DS.Typography.footnote`), 2 lines max, `adjustsFontForContentSizeCategory = true`. Copy is the banner template (see § Copywriting). |
| Layout | Horizontal `UIStackView`: SF Symbol · text, `DS.Spacing.sm` (8pt) spacing, `DS.Spacing.md` (16pt) leading/trailing padding, `DS.Spacing.sm` (8pt) top/bottom padding. Minimum intrinsic height `36pt` (matches `LimitedTrustBannerView`). |
| User interaction | `isUserInteractionEnabled = false` on the stack; the banner is informational, NOT tappable. (The verdict block in the body — § Copywriting — is the read-in-context surface.) |
| Pin behavior | iPhone: pinned to the bottom of the summary header / top of the graph region; never scrolls away (D-16). iPad: pinned to the bottom of the nav bar / top of the split container; spans full width. |
| Accessibility | `isAccessibilityElement = true`, `accessibilityTraits = .staticText`, `accessibilityLabel` = `"Chain integrity: <verdict>. <reason>"` — verdict + reason concatenated with a period+space for VoiceOver prosody. |

### Gesture model (D-04 — resolves spike item (b))

Locked on the `TrustGraphView` and its host `UIScrollView`:

| Gesture | Recognizer | Behavior |
|---------|------------|----------|
| Two-finger pan | `UIScrollView` native pan | Pans the graph canvas when `zoomScale > 1.0`. Disabled (no-op) at `zoomScale == 1.0`. |
| Pinch | `UIScrollView` native pinch | Scales between `minimumZoomScale = 1.0` and `maximumZoomScale = 2.5`. `viewForZooming` returns the `TrustGraphView`. |
| Single-tap on a node | `UITapGestureRecognizer(numberOfTapsRequired: 1)` attached to each `TrustNodeView` | Opens `VerificationBasisSheetViewController` for that node. |
| Single-tap on an edge | `UITapGestureRecognizer(numberOfTapsRequired: 1)` attached to each edge's invisible companion view | Opens `HandoffDetailSheetViewController` for that edge. |
| Double-tap on a node | `UITapGestureRecognizer(numberOfTapsRequired: 2)` attached to each `TrustNodeView`, with `require(toFail:)` on the single-tap recognizer | Animate-recenter+zoom to that node (~250ms ease-in-out, scale `1.8x`). Pre-empts the single-tap → sheet open. |
| Double-tap on empty canvas | `UITapGestureRecognizer(numberOfTapsRequired: 2)` attached to the `TrustGraphView` background | Reset zoom to fit-all-nodes-tight + center (~250ms ease-in-out). |
| Single-tap on empty canvas | (none) | No-op. Tapping empty space does nothing. |
| Vertical scroll on the page body below the graph | host `UIScrollView` (the body's scroll view, **distinct** from the graph's `UIScrollView`) | Scrolls the body. The graph's `UIScrollView` has `panGestureRecognizer.minimumNumberOfTouches = 2` so it does NOT swallow single-finger vertical drags — those propagate to the body scroll view. |

This is the gesture-arbitration resolution called out as spike item (b) in the ROADMAP Phase 9 note. The two-finger-minimum on the graph scroll view is the single most important arbitration choice: it gives the user one-finger to scroll the body, two-finger to pan the graph, and pinch always means zoom-the-graph because pinch already requires two fingers.

### Default zoom + role slots (D-05, D-06 — resolves spike items (a) layout shape, (d) iPhone-tall vs iPad-wide)

**Default zoom:** Fit-all-nodes-tight on first appearance. Computed in `TrustGraphView.layoutSubviews()`:

1. Take the bounding box of all node center coordinates.
2. Inflate by `node.width / 2 + DS.Spacing.lg` (24pt) on every side to keep nodes' chrome inside the visible canvas.
3. Compute `zoom = min(canvasWidth / boxWidth, canvasHeight / boxHeight)`, clamped to `[1.0, 2.5]`.
4. Set the scroll view's `zoomScale = 1.0` (the layout itself does the fitting via Auto Layout; the user's pinch operates on top).

**Fixed role slots** (canvas coordinate system is `0…1` in both dimensions, multiplied by the canvas's actual point dimensions at layout time):

| Role | iPhone (compact) — (x, y) | iPad split left pane (regular) — (x, y) |
|------|---------------------------|------------------------------------------|
| `.shipper` | `(0.18, 0.18)` upper-left | `(0.18, 0.22)` upper-left |
| `.broker` | `(0.50, 0.30)` upper-center | `(0.40, 0.30)` upper-center |
| `.carrier` | `(0.50, 0.55)` center | `(0.50, 0.55)` center |
| `.dispatch` | `(0.82, 0.55)` right-of-carrier | `(0.78, 0.45)` right-of-carrier |
| `.factoring` | `(0.50, 0.85)` lower-center | `(0.82, 0.78)` lower-right |

Coordinates are normalized so the same role-slot geometry rescales into both canvas aspect ratios (D-06). iPhone is taller-than-wide, so the chain reads top-to-bottom (shipper → broker → carrier → factoring with dispatch alongside carrier). iPad split left pane is closer to square (the left 60% of an iPad's safe area is roughly 4:3-ish), so the chain reads top-left → bottom-right with dispatch top-right and factoring bottom-right.

Missing roles are simply absent from the rendered node set; edges between absent role pairs are skipped. A 3-node load (e.g. shipper → broker → carrier, no dispatch, no factoring) renders cleanly in the upper 3 slots.

The fit-all-nodes-tight zoom computation operates on the **present** node positions, so a 3-node load opens larger than a 5-node load.

### Zoom animation parameters (CONTEXT § Claude's Discretion → pinned)

| Parameter | Value |
|-----------|-------|
| Double-tap recenter+zoom animation | `0.25s`, `UIView.AnimationOptions.curveEaseInOut` |
| Target zoom on double-tap-node | `1.8` (within the `[1.0, 2.5]` range; gives a 1.8x view of the tapped node at the canvas center) |

| Compromised pulse animation | `1.2s` per cycle, `0.6 → 1.0 → 0.6` opacity, `CAMediaTimingFunction(name: .easeInEaseOut)`, `repeatCount = .infinity`, `isRemovedOnCompletion = false` |
| Max zoom scale | `2.5` |
| Min zoom scale | `1.0` |

### Snapshot test posture (snapshot brittleness mitigation)

- Snapshot tests use the **static frame** of every animation (the resting state). For the compromised pulse, the snapshot test asserts the halo at `opacity = 1.0` (the upper bound), NOT the animated mid-frame.
- Snapshot tests cover: each verdict × iPhone-portrait + iPad-landscape-split × Dynamic-Type-Large + Dynamic-Type-XXXLarge = 3 × 2 × 2 = 12 snapshot fingerprints for the graph alone. The planner sizes the snapshot budget against this.

## Status Timeline (`StatusTimelineView`) — D-17, D-18

A new `UIView` subclass, file `validationLedger/Features/Loads/Detail/StatusTimelineView.swift`. Renders the 6-pill primary lifecycle plus a current-state expanded card. Lives in the right pane on iPad / below the graph in the iPhone scroll body.

### Stepper (top region)

| Element | Spec |

### Exceptions / explicit non-grid distances

- **44pt minimum touch target** (Apple HIG). The whole `TrustNodeView` honors this via `heightAnchor.constraint(greaterThanOrEqualToConstant: 44)`; the edge tap companion view honors this via a `28pt` band that satisfies the 44pt diagonal at every realistic edge angle (smallest 90-degree-angle hit area is `28 × ~38pt ≈ 47pt diagonal`). 44 is not a `DS.Spacing` token; it is the explicit touch-target floor.
- **Halo inset `-6pt`** outside the node chrome. 6 is on the 2pt grid but NOT on the 4pt grid; this is a documented exception. Rationale: 6pt halo is the visual sweet spot — 4pt is too tight and visually merges with the chrome edge; 8pt looks like a separate ring rather than a halo. The 6pt distance is locked here so the executor doesn't hunt for it.
- **Edge stroke `2pt`** and **arrowhead `7pt × 7pt`** — geometry inside `CAShapeLayer`, not in the auto-layout spacing grid.
- **0.5pt node chrome border** — geometry inside `CALayer.borderWidth`, not in the auto-layout spacing grid.
- **8pt corner radius** on current-state card and verdict block — matches Apple's standard interior-card radius on iOS 17+. 12pt corner radius on node chrome — slightly larger for the larger touch target.
- **Split-pane fractional widths** (`0.60`, `0.40`) — these are layout proportions, not spacing distances; expressed as multipliers, not as `DS.Spacing` members.
- **Default-zoom scale `1.0`** and **double-tap-zoom scale `1.8`** — these are transformations, not spacings.

## Typography

Phase 9 uses the existing `DS.Typography` tokens, all backed by `UIFont.preferredFont(forTextStyle:)`. Every label MUST set `adjustsFontForContentSizeCategory = true`. The table below pins the **four roles Phase 9 declares**.

| Role | `DS.Typography` token | Text style | Size (default) | Weight | Line height (default) | Used for |
|------|----------------------|------------|----------------|--------|------------------------|----------|

A fifth token (`DS.Typography.caption` — `.caption1`) is used for the **node role label inside `TrustNodeView`** in the trust graph — the `.caption1` size is more compact than `.footnote` at fit-all-tight zoom, keeping the three-line node stack (role / badge / name) inside the node chrome. This is the only place `.caption1` appears in the screen; it is in the codebase's existing `DS.Typography.caption` token (not new), and its existence here is documented because the role label inside the node fits visually only at `.caption1`-scale at the smallest zoom level.

**Weights:** exactly two — **regular (400)** for body/title/caption/footnote and **semibold (600)** for headings/reference numbers/button titles. This is what the iOS `.headline` vs `.body`/`.title1`/`.footnote` styles already give for free. No manual `.withWeight(...)` overrides, no bold/light/medium.

**Sizes:** exactly four roles declared (28 / 17 / 17 / 13), plus the one documented exception (`.caption1` ~12pt for the node role label only). Body and Heading share the 17pt point size but differ by weight — the standard iOS pairing and counts as the two distinct *roles* the contract requires.

### Reference-number visual anchoring

The reference number (e.g. "VL-1023") is the strongest hierarchical anchor on the entire screen. It uses `.headline` (17pt semibold). The same convention from Phase 8 (load-list cell) extends to the detail screen's pinned header — users learn "the bold thing is the load ID" across both surfaces.

### Dynamic Type behavior

- Every label is `adjustsFontForContentSizeCategory = true`. The user's Dynamic Type setting (Default through AX5) is honored.
- The graph node chrome height is intrinsic-content-driven; at AX5 a node can grow to ~120pt tall. The fit-all-nodes-tight zoom recomputes against the actual node heights, so the graph rescales correctly.
- The pinned summary header truncates with `.byTruncatingTail` at AX5+ when origin→destination overflows; the reference number always stays visible (highest content-hugging priority).
- The banner allows up to 2 lines and grows the banner intrinsic height at AX5 (per `LimitedTrustBannerView`'s precedent).

Accent is **NOT** applied to:
- Body text, separators, the screen background, the surface fills, the freight-row labels.
- Edge strokes when chain is clean (those use `DS.Colors.separator`, neutral grey).
- The node chrome border (neutral separator grey).

### Pre-fraud-tier color invariants (the four-state visual language — D-15, resolves spike item (a))

The **chain-integrity tier** drives a tiered visual response. This is the marquee fraud-signal language. The four states are: `clean`, `caution`, `compromised`, plus the fallback **fail-closed-to-compromised** decoded state (an unknown server superstring decodes to `.compromised` per `ChainIntegrity.swift` line 83 — D-09 parity, opposite direction).

| Tier | Banner | Flagged nodes (halo) | Flagged edges | Unflagged nodes/edges |
|------|--------|----------------------|---------------|------------------------|
| `clean` | Not rendered (banner view is `isHidden = true` and removed from stack) | No halo | No special treatment — solid neutral-grey stroke | Full opacity, standard render |
| `caution` | Yellow background, dark-label foreground, triangle SF Symbol, copy = `chainIntegrity.reason` | Yellow halo (`DS.Colors.caution`), inset `-6pt`, no animation | Yellow dashed (`lineDashPattern = [6, 4]`), arrowhead in yellow | Dimmed to `0.5` opacity — `alpha = 0.5` on both `TrustNodeView` and edge `CAShapeLayer.opacity` |
| `compromised` | Red background, white foreground, octagon SF Symbol, copy = `chainIntegrity.reason` | Red halo (`DS.Colors.destructive`), animated pulse (`opacity 0.6 → 1.0 → 0.6`, `1.2s`, `easeInEaseOut`, `repeatCount = .infinity`) | Red dashed (`lineDashPattern = [6, 4]`), arrowhead in red | Dimmed to `0.5` opacity (same as caution) |

**Pulse is the "this is BAD" tell; color is the "how bad" tell.** Pulse fires ONLY on `compromised`. Color (yellow vs red) distinguishes `caution` from `compromised`. (D-15 — explicit invariant.)

**The 5 colors used in the graph rendering are exactly:** `DS.Colors.background`, `DS.Colors.surface`, `DS.Colors.separator`, `DS.Colors.caution`, `DS.Colors.destructive`. Plus the per-node verification badge colors (`.verified` blue / `.pending` yellow / `.unverified` neutral-grey / `.flagged` red), all of which are already on the Phase 8 verification-badge ramp. **No other color is permitted in the graph rendering.** Adding a 5th chain-integrity verdict (e.g. "quarantined") requires changing `ChainIntegrity.Verdict` upstream, which would fail decode at the Phase 7 contract layer (and any new verdict degrades to `.compromised` via the fail-closed decoder until UI is updated).

### Status-stepper color (does NOT reuse the fraud ramp)

The current-pill in the status timeline uses `DS.Colors.primary` (blue) — the same blue as the `.verified` badge. The stepper is a logistics surface, NOT a fraud surface. Phase 8 already established that the verification (TRUST-02) ramp and the status (LoadStatus) ramp are kept distinct; Phase 9 extends this by making the **timeline current-pill** the only place blue appears in the entire timeline section. The completed pills are neutral-grey, the future pills are outline-only — no chromatic gradient on the stepper.

### Other non-blue/non-red colors

The system neutrals (`.tertiarySystemFill`, `.systemGray5`, `.systemGray6`) appear via the reused `LoadStatusBadgeView` (Phase 8). No new neutrals introduced here.

## State Machine

The load-detail screen has exactly three mutually exclusive top-level states (D-20 — no `.empty` state).

| State | Trigger | What renders | Test fixture (Phase 7 + Phase 9 re-author) |
|-------|---------|--------------|---------------------------------------------|
| `.loading` | First appearance OR `Try again` button tap from `.error` | `LoadDetailSkeletonView` filling the VC's view. iPhone: full-silhouette skeleton. iPad: split-silhouette skeleton. | The injected-latency fixture from Phase 7 D-14 — re-applied to a detail endpoint call |
| `.loaded(load, chainOfTrust)` | Successful fetch with both `load` and `chainOfTrust` non-nil | The full composition: pinned header + banner (if !clean) + trust graph + timeline + body. iPhone or iPad layout per `traitCollection.horizontalSizeClass`. | All 12 `load-detail-VL-*.json` fixtures from Phase 7 D-13 — re-authored in Phase 9 (D-14) to populate `prior_relationships` arrays |
| `.error(message)` | Network error, decode error, or server-error response (including 404) | `UIContentUnavailableView` with the error heading + body + "Try again" CTA from § Copywriting | A new `load-detail-error.json` fixture (likely additive to Phase 7's matrix; planner confirms in plan-time research) |

The `.loading` → `.loaded` / `.error` transition is **abrupt** (no crossfade) — matches the Phase 4/6 ADR-0002 abrupt-replace posture established by `LimitedTrustBannerContainerViewController` and the Phase 8 cell skeleton swap.

There is NO retry/refresh affordance on `.loaded` state. The detail screen is a one-shot fetch per CONTEXT Deferred (pull-to-refresh on detail is a post-v1.1 concern when real-time updates land).

## VoiceOver / Accessibility (resolves ROADMAP spike item (c))

### Traversal order (D-21)

| Layout | Traversal order |
|--------|-----------------|
| iPhone (compact) | Pinned header → chain-integrity banner (if rendered) → trust graph (as one container — see D-22) → status timeline stepper (as one combined element) → status timeline current-card (own element) → freight detail rows (each row is its own combined element) → parties inline list (each row is its own element) → chain-integrity verdict block (if rendered) → end-of-screen |
| iPad (regular) | Banner (if rendered) → right pane FIRST (pinned header → status timeline → freight rows → parties → verdict block) → left pane SECOND (trust graph as one container) → end-of-screen |

The iPad traversal-right-pane-first order is **intentional** — VoiceOver users read prose freight metadata more efficiently than spatial node-graph data, so the freight-rich right pane comes first. The user can pre-jump to the graph with the rotor by selecting the "Trust graph" accessibility container.

### Graph accessibility container (D-22)

`TrustGraphView` sets `isAccessibilityElement = false` (so it's a *container*, not a leaf) and `accessibilityElements` to an ordered array:

1. The 5 (or fewer) `TrustNodeView` instances in **fixed role order**: `shipper, broker, carrier, dispatch, factoring`. Roles that are absent from the load are skipped.
2. The `TrustEdge` invisible-companion views in **deterministic order**: sorted by `(fromPartyID, toPartyID)` lex order.

Each `TrustNodeView`'s `accessibilityLabel`:

> *"{Role display name}, {display name}, verification state: {state}, KYC {basis summary}, {implicated suffix if applicable}"*

Concrete examples:
- *"Broker, Acme Brokerage, verification state: verified, KYC verified 2 months ago, device bound."*
- *"Carrier, Sketch Logistics, verification state: flagged, KYC not completed, device not registered, USDOT authority revoked. Implicated in chain compromise."* (The "Implicated in chain compromise" suffix is appended when `partyID ∈ implicatedNodeIDs` so VoiceOver users get the fraud signal as part of the label, not just visually.)

Each edge invisible-companion view's `accessibilityLabel`:

> *"Handoff from {fromRole.displayName} to {toRole.displayName}, relationship state: {state}, {implicated suffix if applicable}"*

Concrete example:
- *"Handoff from broker to carrier, relationship state: unverified. Implicated in chain compromise."*

`accessibilityTraits = .button` on every node and every edge — so VoiceOver double-tap activates the sheet (same code path as a sighted user's single-tap).

### Pinch-zoom disabled while VoiceOver runs

When `UIAccessibility.isVoiceOverRunning == true`:
- `UIScrollView.minimumZoomScale = UIScrollView.maximumZoomScale = 1.0` (no zoom).
- Double-tap gestures are disabled (VoiceOver uses single-finger double-tap as its activate gesture; if our recognizer is active it conflicts with VoiceOver's input model).
- The graph stays at fit-all-nodes-tight default zoom.
- `UIAccessibility.didChangeNotification` observer re-enables the gestures when VoiceOver turns off.

### Other accessibility provisions

- The compromised pulse animation respects `UIAccessibility.isReduceMotionEnabled` — when reduce-motion is on, the halo is rendered solid at `opacity = 1.0` (no pulse). Color (red) still signals "compromised"; motion does not.
- Every label sets `adjustsFontForContentSizeCategory = true`.
- All SF Symbols use `UIImageSymbolConfiguration` with `pointSize` derived from the parent label's font, so symbols scale with Dynamic Type.
- The skeleton state's shimmer animation is suppressed when reduce-motion is on (the skeleton stays static-grey).
- The status timeline stepper sets `accessibilityLabel` to a single combined string (the 6-pill structure is overwhelming if rendered as 6 separate elements): e.g. *"Status timeline. Posted, Tendered, Accepted complete. Dispatched current. In transit, Delivered upcoming."*

## Open Questions Flagged for the Planner (do not block UI-SPEC approval)

1. **`PriorRelationship.counterpartyDisplayName` rendering decision.** UI-SPEC documents the optional field but defers the in-row rendering decision (whether to render "Broker → Carrier" alone or "Broker (Acme Brokerage) → Carrier"). The planner picks one in plan-time; if the latter is chosen, ensure the framing string truncates gracefully when display names are long.
2. **Edge color rule for `.unverified`-relationship edges in `.clean` chains.** UI-SPEC's current rule: a clean chain renders all edges with solid neutral-grey stroke regardless of per-edge `relationshipState`. Alternative: render `.unverified` edges with a thin dashed neutral stroke even in clean chains, to expose per-edge ambiguity. The CONTEXT § Claude's Discretion explicitly delegates this to UI-SPEC; the planner can finalize this in plan-time research if they want to surface per-edge verification independent of chain integrity. **Default chosen here:** solid neutral-grey regardless of per-edge state — the chain-integrity verdict is the authoritative signal, and adding a per-edge visual would muddy the four-state language without adding actionable information.
