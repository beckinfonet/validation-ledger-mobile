<objective>
The persistence + vocabulary foundation for Phase 5: the encrypted on-disk store that makes KYC resumable (KYC-06 / UPL-02), the models it persists, and the rejection-reason-code enum that the status screen renders (KYC-05 / D-11).

Purpose: D-02 says the in-progress KYC session — un-uploaded artifact `Data`, `uploadID`s, per-chunk progress — survives cold boots indefinitely. `Core/Storage` is currently Keychain-only; this plan adds the file-backed store. The artifact `Data` is multi-MB so it cannot go in the Keychain (RESEARCH "Alternatives Considered"). It is built first because `KYCUploader` (plan 04) and the capture flow (plan 05) both inject it.

Output: `KYCSession` + `ArtifactUploadState` models, `RejectionReasonCode` enum, `KYCSessionStore` (`NSFileProtectionComplete`), and the rejection-reason copy strings.

TDD plan: this is pure logic — RED scaffolds from plan 01 (`KYCSessionStoreTests`, `RejectionReasonCodeTests`) drive RED→GREEN→REFACTOR.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| In-memory KYC session ↔ device storage | Sensitive identity bytes (DL, face) cross to disk |
| Backend rejection code → iOS copy | Untrusted code string maps to a UI sentence |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | Information Disclosure | KYCSessionStore on-disk artifact Data (DL, face images) | mitigate | Every file + the containing directory written with `NSFileProtectionComplete` — encrypted at rest, tied to the device passcode; readable only while the device is unlocked (RESEARCH V8 Data Protection) |
| T-05-02-02 | Tampering | Hand-rolled encryption of the KYC store | mitigate | Use OS-managed `NSFileProtectionComplete` exclusively — `grep` gate asserts zero `AES`/`SecKey`/`CryptoKit` in the store (RESEARCH "Don't Hand-Roll #1") |
| T-05-02-03 | Tampering | Unknown/malicious backend rejection code injected into UI | mitigate | `RejectionReasonCode.copy(for:)` maps only known codes; an unrecognized code degrades to a fixed generic sentence — the raw string never reaches the UI (D-11 fallback) |
| T-05-02-04 | Information Disclosure | KYC session persisted to UserDefaults or a plain file | mitigate | Store writes only via `Data.write(options: .completeFileProtection)`; `ban_userdefaults_tokens` SwiftLint rule already blocks UserDefaults token writes |
| T-05-02-05 | Repudiation | KYC session wiped by an unrelated logout, losing the user's work | accept | D-02: logout deliberately does NOT wipe the on-disk session — the store is never wired into `LogoutService`; the store's header comment documents this invariant |
| T-05-02-SC | Tampering | npm/pip/cargo installs | accept | Phase 5 installs zero packages (RESEARCH Package Legitimacy Audit); no install task in this plan |
</threat_model>
