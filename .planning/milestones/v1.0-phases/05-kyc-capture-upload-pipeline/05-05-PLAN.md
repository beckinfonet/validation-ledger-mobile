<objective>
The KYC capture flow: `KYCCoordinator` plus the six capture screens, the per-shot Use/Retake preview, the DL extraction-confirmation screen, the camera-permission-denied screen, the client-side DL format validator, and the KYC-03 DataScanner device-CI smoke test. KYC-01 (flow orchestration), KYC-02 (Vision-gated face capture), KYC-03 (DataScanner DL OCR), KYC-04 (GPS-tagged vehicle photos).

Purpose: this is the user-facing capture half of Phase 5 — six identity/vehicle artifacts captured on UIKit screens (CLAUDE.md hard constraint: camera surfaces are UIKit, never SwiftUI). It sits on top of the capture services from plan 03 (`CameraSession`, `FaceQualityGate`, `GPSMetadataInjector`, `GeoContext`) and the upload pipeline from plan 04. Per D-01 (pipelined upload), each artifact begins uploading the instant it is captured + confirmed — the coordinator kicks `KYCUploader.upload(...)` while the user keeps shooting.

Output: `KYCCoordinator` + 9 capture-flow files + the DL format validator + the filled-in KYC-03 device-test. This plan has a `checkpoint:human-verify` because live camera/scanner surfaces cannot be exercised in the simulator (RESEARCH Pitfall 1) — `autonomous: false`. Task 2 is split into 2a (face capture + DL screens) and 2b (DL back + vehicle + preview + permission + KYC-03 device-test) so no task exceeds ~6 files.
</objective>
