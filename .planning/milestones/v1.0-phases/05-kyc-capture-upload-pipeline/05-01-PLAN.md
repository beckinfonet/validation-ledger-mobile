APIEndpoint protocol (validationLedger/Core/Networking/APIEndpoint.swift):
  public protocol APIEndpoint<Response>: Sendable {
    associatedtype RequestBody: Encodable & Sendable
    associatedtype Response: Decodable & Sendable
    var path: String { get }
    var method: HTTPMethod { get }
    var body: RequestBody? { get }
  }
  - HTTPMethod enum: .get .post .put .delete
  - EmptyBody sentinel exists for GET endpoints.

APIClient.buildRequest (validationLedger/Core/Networking/APIClient.swift) currently sets:
  Accept header always; Content-Type when body present. No per-endpoint header path.
  requestInterceptors run AFTER buildRequest — IdempotencyInterceptor reads the existing
  Idempotency-Key header and does NOT overwrite a caller-supplied value.

OTPVerifyEndpoint.Response (validationLedger/Core/Networking/Endpoints/OTPVerifyEndpoint.swift):
  public struct Response: Decodable, Sendable {
    public let sessionToken: String
    public let role: String
    public let userID: String
    private enum CodingKeys: String, CodingKey { case sessionToken, role, userID = "userId" }
  }

KYCUploadCommitEndpoint (the structural template for KYCSubmitEndpoint):
  nonisolated public struct KYCUploadCommitEndpoint: APIEndpoint {
    public struct RequestBody: Encodable, Sendable { public let uploadID: String
      private enum CodingKeys: String, CodingKey { case uploadID = "uploadId" } }
    public struct Response: Decodable, Sendable { public let artifactID: String; public let status: String
      private enum CodingKeys: String, CodingKey { case artifactID = "artifactId", status } }
    public let path = "/kyc/upload/commit"
    public let method: HTTPMethod = .post
    public let body: RequestBody?
    public init(uploadID: String) { self.body = RequestBody(uploadID: uploadID) }
  }

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01-01 | Tampering | OTPVerifyEndpoint.Response decoding | mitigate | `kycStatus` is `String?` — a malformed/absent value decodes to nil rather than throwing; downstream routing (plan 07) treats nil as "not verified" (fail-closed to the KYC gate, not the role shell) |
| T-05-01-02 | Spoofing | BGTask identifier in Info.plist | accept | The identifier is a public constant; iOS scopes task scheduling to the app's own bundle — another app cannot submit work under it. No secret involved |
| T-05-01-03 | Information Disclosure | New KYC fixtures committed to the repo | mitigate | Fixtures contain only synthetic test data (`art-face-001`, fake reason codes) — no real PII; this is the established Phase 2 fixture convention |
| T-05-01-SC | Tampering | npm/pip/cargo installs | accept | Phase 5 installs zero packages (RESEARCH Package Legitimacy Audit — vacuously satisfied); no install task in this plan |
