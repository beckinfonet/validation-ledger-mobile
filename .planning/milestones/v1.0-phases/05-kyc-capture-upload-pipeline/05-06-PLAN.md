<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend KYC verdict → iOS UI | `overallStatus` + per-artifact `rejectionReason` cross from an untrusted source |
| Submit action → backend | The final KYC-submission call |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06-01 | Tampering | A submitted KYC where not all artifacts actually reached the backend | mitigate | Submit is disabled until all 6 `ArtifactUploadState`s are `committed` (server-acked); the finalizer carries the 6 server-issued `artifactID`s — a submitted KYC always means all artifacts are confirmed on the backend (D-03) |
| T-05-06-02 | Tampering | Malicious/unknown backend rejection code rendered as UI text | mitigate | `rejectionReason` strings map through `RejectionReasonCode.copy(for:)`; an unrecognized code degrades to a fixed generic sentence — the raw string never reaches the UI (D-11) |
| T-05-06-03 | Information Disclosure | Identity-document thumbnails cached unencrypted by the image library | mitigate | Thumbnails render from the locally-held preview image / the encrypted `KYCSessionStore`; `Nuke`'s disk cache is not used for KYC artifact images — they are not network URLs |
| T-05-06-04 | Spoofing | Status screen polling a stale verdict | accept | D-09: fetch-on-appear + pull-to-refresh, no background polling — the verdict is re-fetched every time the screen appears; M3 push notifications make it reactive |
| T-05-06-SC | Tampering | npm/pip/cargo installs | accept | Phase 5 installs zero packages (RESEARCH Package Legitimacy Audit); `Nuke` is reused, not newly installed |
</threat_model>
