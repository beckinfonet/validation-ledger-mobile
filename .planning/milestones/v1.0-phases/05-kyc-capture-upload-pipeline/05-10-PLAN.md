<objective>
Close the Test 10 gap: after an ungraceful force-quit mid-capture and relaunch, the
KYC vehicle-capture screen's shutter is dead — tapping it does nothing and the flow
cannot advance.

Two compounding `AVCaptureSession` lifecycle defects (diagnosed in
`.planning/debug/kyc-force-quit-camera-stuck.md`):

1. `AVFoundationCameraSession.capturePhoto()` bridges the still capture through a
   `withCheckedThrowingContinuation` resumed ONLY inside
   `photoOutput(_:didFinishProcessingPhoto:error:)`. When the capture source is dead
   that delegate never fires, the `await` hangs forever, and the capture VM's
   `captureInFlight` guard then makes every later shutter tap a silent no-op.
2. `AVFoundationCameraSession` registers zero `AVCaptureSessionRuntimeError` /
   interruption observers and binds session start/stop only to VC view lifecycle — a
   force-quit skips `viewWillDisappear`, the prior session is never `stopRunning()`-ed,
   the `mediaserverd` capture-source connection is torn down abruptly
   (`FigCaptureSourceRemote err=-17281`), and the relaunched session can fail to
   re-establish a live source while `AVCaptureConnection.isActive` still reads `true`.

Purpose: all camera/KYC surfaces are UIKit and a stuck shutter is a hard blocker — the
KYC flow cannot complete. The fix honors the existing protocol-backed camera
architecture (`CameraSession` protocol + `AVFoundationCameraSession` Default impl,
`@MainActor` API + `nonisolated` delegate callbacks) rather than rewriting it.

Output: a timeout-bounded `capturePhoto()`, runtime-error/interruption observers that
rebuild a dead session, app-lifecycle session control, and capture VMs whose `.failed`
path re-arms the shutter.
</objective>

From validationLedger/Core/Identity/Capture/CameraSession.swift —
the error surface to extend and the capture entry point to bound:
```swift
public enum CameraSessionError: Error, Sendable {
    case cameraUnavailable
    case permissionDenied
    case configurationFailed
    case captureFailed(Error)
}
// capturePhoto() today — the unbounded await with a single resume site:
public func capturePhoto() async throws -> AVCapturePhoto {
    guard Self.isCameraAvailable else { throw CameraSessionError.cameraUnavailable }
    return try await withCheckedThrowingContinuation { continuation in
        self.captureContinuation = continuation                 // stored
        let settings = AVCapturePhotoSettings()
        photoOutput.capturePhoto(with: settings, delegate: self)
    }
}
// resumed ONLY here:
public nonisolated func photoOutput(_ output:didFinishProcessingPhoto:error:) {
    Task { @MainActor [weak self] in
        ... self.captureContinuation?.resume(...) ; self.captureContinuation = nil
    }
}
```
The class is `@MainActor public final class AVFoundationCameraSession: NSObject,
CameraSession, AVCapturePhotoCaptureDelegate, AVCaptureVideoDataOutputSampleBufferDelegate`.
It owns `private let session = AVCaptureSession()`, `private let photoOutput`,
`private let videoDataOutput`, `private let sessionQueue`. Session mutation goes
through `configureSessionInputs(position:)` (the `nonisolated` config block) and
`start()` / `stop()` (both `nonisolated`, hop onto `sessionQueue`).
`startAuthorizedSession(position:)` resolves permission then `configureSessionInputs`
+ `start()`. The session start/stop is currently driven ONLY by
`VehicleCaptureViewController.viewWillAppear → viewModel.start()` and
`viewWillDisappear → viewModel.stop()`.

From VehicleCaptureViewModel.swift / FaceCaptureViewModel.swift —
the shutter-wedge mechanism:
```swift
private var captureInFlight = false
func capture() {
    guard !captureInFlight else { return }    // <- silent no-op once stuck
    captureInFlight = true
    state = .capturing                        // <- VC disables shutterButton
    Task { [weak self] in await self?.performCapture() }
}
private func performCapture() async {
    // ... geoContext.freshLocation() ...
    let photo: AVCapturePhoto
    do { photo = try await cameraSession.capturePhoto() }   // <- hangs forever
    catch {
        captureInFlight = false                              // re-arm — already correct
        state = .failed("The camera isn't available on this device.")
        return
    }
    // ...
}
```
The catch block ALREADY sets `captureInFlight = false` — so once `capturePhoto()`
*throws* (instead of hanging), the existing `.failed` path re-arms the shutter
correctly. The fix in the VMs is the error copy, not the control flow:
`VehicleCaptureViewController.handle(state:)` renders `.failed(message)` by setting
`cueLabel.text = message` and `shutterButton.isEnabled = false` — so a timeout that
lands in `.failed` would DISABLE the shutter. A timeout needs a state the VC renders
with the shutter ENABLED so the user can retry.

From VehicleCaptureViewController.handle(state:) — existing state→UI mapping:
`.ready` / `.locationUnavailable` → shutter ENABLED;  `.capturing` /
`.failed` → shutter DISABLED. `.locationUnavailable` is the precedent for a
recoverable, shutter-enabled error state with cue copy.

App-lifecycle precedent: `SceneDelegate` already uses
`NotificationCenter.default.addObserver(forName: UIApplication.didBecomeActiveNotification,
...)` and stores observer tokens removed in `sceneDidDisconnect` + `deinit`.
`UIApplication.didEnterBackgroundNotification` / `willEnterForegroundNotification`
are the standard app-lifecycle notifications. iOS 17 deployment — Swift Concurrency,
`Task.sleep(for:)`, and structured task groups are all available with no backport.
