TrustTier — closed-set enum, RawRepresentable as String, Codable. Round-trips through
Keychain as a string exactly like attestedKeyId. Default fallback value is `.softwareOnly`.
The hardware-attested case is `.hardwareAttested` (the banner is hidden only at that tier).

AttestedKeyStore existing accessor pattern (validationLedger/Core/Attestation/AttestedKeyStore.swift:43-60):
  - `readAttestedKeyId() throws -> String?` — `keychain.get(.attestedKeyId)`, translates
    `KeychainError.itemNotFound` to `nil`.
  - `writeAttestedKeyId(_:) throws` — `keychain.set(Data(...), for: .attestedKeyId,
    accessibility: .afterFirstUnlockThisDeviceOnly)`.
  - `AttestedKeyStore` is initialised `AttestedKeyStore(keychain:)`; it holds a `keychain`
    (a KeychainStore) and a `// MARK: - attestedKeyId` / `// MARK: - lastHeartbeatAt` layout.

KeychainKey existing attestation-group statics (KeychainKey.swift:35-40):
  - `static let attestedKeyId = KeychainKey(rawValue: "device.attestedKeyId")`
  - `static let lastHeartbeatAt = KeychainKey(rawValue: "device.lastHeartbeatAt")`
  - The `device.` prefix is the grouping convention; `session.` keys (e.g. `session.kycStatus`)
    are the ones wiped by `deleteAll(under: .session)`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend → iOS (`/device/register` response) | `trustTier` arrives as untrusted wire data; decoded by a typed `Decodable` endpoint downstream (Plan 02). This plan only stores whatever value Plan 02 hands it. |
| iOS process → Keychain | `device.trustTier` is written/read across the process↔Keychain boundary; `.afterFirstUnlockThisDeviceOnly` items are not user-editable on a non-jailbroken device. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01-01 | Tampering | `device.trustTier` Keychain item — a client-tampered tier could suppress the limited-trust banner | accept | `trustTier` is backend-driven (Phase 4 D-12); the item is only ever written from a `/device/register` response, and `.afterFirstUnlockThisDeviceOnly` Keychain items are not editable on a non-jailbroken device. The banner is informational, not an access gate (Phase 4 D-11) — impact is bounded. |
| T-06-01-02 | Information Disclosure | `trustTier` value in Keychain / logs | mitigate | `TrustTier` is a closed-set enum rawValue (no PII); this plan adds no `Logger` calls. `device.trustTier` lives in Keychain, never `UserDefaults` or a plain file (CLAUDE.md / SEC-03). |
| T-06-01-03 | Tampering | Unknown/garbage wire value re-hydrated as a forged tier | mitigate | `readTrustTier` uses `TrustTier(rawValue:)` — an unknown string yields `nil`, which falls back to the safe `.softwareOnly` default downstream (fail-safe, never fails open to `.hardwareAttested`). |
| T-06-01-SC | Tampering | npm/pip/cargo installs | mitigate | N/A — Phase 6 installs zero packages (06-RESEARCH.md Package Legitimacy Audit: not applicable). No package-manager install tasks in this plan. |
</threat_model>
