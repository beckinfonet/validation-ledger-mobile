<objective>
Fix the test-isolation defect where `AppContainerLoadEndpointsConfigSwapTests` tests `mockConfigEndToEndSwap` and `mockConfigEndToEndDecode` fail on full-suite runs.

Root cause (per 09-VERIFICATION.md ~line 131): `MockLoadFixtureRegistry.hasRegisteredAppDefaults` is a process-lifetime static idempotency guard (the WR-01 fix). The first test in the suite triggers `AppContainer.init`'s DEBUG block, which calls `registerAppDefaults()` and flips the guard to `true`. The suite's `resetMockURLProtocol()` helper clears `MockURLProtocol`'s handler arrays but does NOT clear that static guard. So when a later test constructs a fresh `AppContainer`, `registerAppDefaults()` sees `hasRegisteredAppDefaults == true`, skips re-registration, and the Load handlers are absent — every Load request 404s.

The production seam already exists: `MockLoadFixtureRegistry.resetForTestOnly()` (added by Phase 10, `MockLoadFixtureRegistry.swift` lines 113-125, `#if DEBUG`-gated). The Phase 7 test suite was written before that seam existed and never adopted it. Sibling suites `MockLoadFixtureRegistryActionToggleTests` and `CarrierDirectoryMockTests` already call it correctly — this plan brings the Phase 7 suite into line.

Purpose: restore a green full-suite run; the two failing tests are the last known non-Phase-9 failures.
Output: a one-line addition to the `resetMockURLProtocol()` helper in `AppContainerNetworkConfigTests.swift`.

NOTE: This is a TEST-INFRASTRUCTURE fix only. No production file changes. The WR-01 idempotency guard in `MockLoadFixtureRegistry.swift` is correct and stays untouched — it prevents handler-array accumulation on DevMenu role swaps.
</objective>

```swift
enum MockLoadFixtureRegistry {

}
```
